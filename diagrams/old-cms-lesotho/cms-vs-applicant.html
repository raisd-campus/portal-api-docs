1. Three flows

[A]Newer Lesotho CMS (screenshots)
[B]Old campus2_lesotho app_*
[C]Raisd Applicant Demo

[A] Newer Lesotho CMS — staff-centric

Applicant record (programme · score · rank · intake)
  → Document Review (LGCSE scan + extract, Sesotho subjects)
  → Admissions Review
       Academic recommend → QA recommend → Registrar recommend
  → Admissions payment VERIFIED (Loti M)
  → Accepted / enrolled

[B] Older Lesotho CMS — online + staff statuses

Applicant UI → app_applicationform_online (+ education/guardian SPs)
  + LGCSE docs (app_docfile / flat Subject1–6)
  + fee proof (b_paymentverification, LSL/M)
  → FacultyStatus → AQA* → RegistryStatus
  → Offer (r_stdofferletter*) → student create

SPs: InsertOnlineApp*, UpdateOnlineApp*, FetchOnline*. Rank/score not in old dump.

[C] Raisd Applicant Demo — 8 Oct 2026

Sign-in → Consent → Study (Campus + 3 prefs) → Personal → Academic → Documents → Fee
  → Submit → Application Progress
       1. Payment Proof — Bursary
       2. Document Check — QA → DEMO Eligibility Letter
       3. Confirm Eligibility — Applicant
       4. Offer Letter — Registry → Accept Enrolment
  → Handoff v2 → Student Documents (local mock)

Live Demo URL: raisd-applicant-portal.vercel.app. Hosted letter/campus accept still local-mock-only.

4. Critical gaps for Lesotho M4 Live

  1. LGCSE / Sesotho extract — model + UI + staff Document Review parity.
  2. LSL application fee verification — campus finance profile + durable proof store.
  3. Staff Academic → QA → Registrar — Staff portal / Portal API; not Applicant-only.
  4. Rank/score — confirm with Admissions; Schema if required.
  5. Official offer letter — replace DEMO PDF with campus print/sign path.
  6. CMS write-back (CAP-53) — Applicant never writes CMS directly.
  7. Hosted letter/campus methods — Portal API must catch up to local mock.
  8. Eligibility Letter product fit — validate with Registry vs CMS recommend chain.

What Raisd Demo already covers well

  • Validated multi-step apply, drafts, messages, immutable snapshots
  • Campus on Study Preferences (Lesotho selectable)
  • Sequential payment → document verification
  • Two-stage letter mock + Student document preservation (local)
  • Clear DEMO labelling on generated PDFs

5. Recommended next work

  1. Confirm with Registry whether Eligibility Letter + applicant confirm are Lesotho policy or Demo scaffolding.
  2. Specify LGCSE extract fields in Schema + CAP-03.
  3. Staff portal MVP: payment/document verify, Academic/QA/Registrar recommend, release offer.
  4. Portal API: persist campus + letter workflow for hosted Demo; then Live CMS adapter.
  5. Keep updating FE gap matrix and #gap-x — do not fork a third spreadsheet.
