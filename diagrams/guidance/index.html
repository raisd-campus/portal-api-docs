Registration — numbered steps in order.

  1. Applicant submits the application with fee proof (applicant portal).
  2. Bursary verifies fee on Admissions Payments — see flow.
  3. QA verifies files on Document Review — see flow.
  4. Academic → QA → Registrar complete recommendation on Review (progress n/3) — see flow.
  5. Staff use Applicants master tabs when they need the full file.
  6. Applicant confirms eligibility and accepts the offer on the applicant portal.
  7. Student continues as an enrolled student; Registry uses the student file.

Module / term registration

  1. Student requests registration (student portal) or Registry starts Register student on the student file.
  2. Attach sponsors / NMDS when required — see Sponsors flows.
  3. Registry clears the request on Registration Requests (Details → Clearance → History) — see flow.

Admissions · Review & Applicants

Admissions Newer CMS Who: Academic reviewer · QA · Registrar Route: /admissions/admissions-review · /admissions/applicants

Work the recommendation queue first, then open the applicant file tab by tab. Each step shows one screen.

Flow A — Work your Review queue

Who: Academic reviewer · QA · Registrar (progress n/3)

This is the admissions recommendation queue. Staff open pending applications, read Review Progress (recommended / not recommended / pending / Your Activity), and record their recommendation for the current gate.

Completing a recommendation advances the application along Academic → QA → Registrar. It does not enrol the student and does not replace Document Review or Admissions Payments.

  • Use this when you need to recommend or not-recommend from the work queue.
  • Payment and document checks happen on separate desks before or alongside this path.
  • Progress n/3 shows how many of the three gates are done.

Admissions · Document Review

Admissions Newer CMS Who: QA / document verifier Route: /admissions/documents

Check every submitted file before admissions continues. One screen per step.

Flow — Verify documents

Who: QA / document verifier

Document Review is the campus queue for checking every uploaded admissions file (academic records, certificates, application forms, identity, proof of payment, and similar types).

Staff filter by type, open each item, and accept or reject so admissions can continue. Extract / subject settings for LGCSE-style analysis live under Settings → Document analysis when configuration is needed.

  • Rejecting a document usually sends the applicant back to fix the file.
  • This desk does not replace fee approval or the Academic/QA/Registrar recommendation gates.

Admissions · Admissions Payments

Admissions / Finance Newer CMS Who: Bursary / Finance Route: /admissions/payments

Verify the application fee proof only. Approving payment does not enrol the student.

Flow — Verify fee proof

Who: Bursary / finance admissions staff

Admissions Payments is where application fee proof is matched to the expected charge and approved or rejected. Review Progress shows what is waiting.

Approving payment unlocks later admissions steps but does not enrol the student into a programme or register modules.

  • Campus-wide payment rules may be configured under Settings → Payments.
  • Keep this desk for fee proof; catalogue amounts for other fee types live under Fees & Fines.

Finance · Fees & Fines

Finance Newer CMS Who: Finance HOD / fee administrators Route: /finance/pricing/fees-and-fines

Browse the catalogue chip by chip, then configure a rate. Amounts on staging are examples only.

Flow — Catalogue and rates

Who: Finance / bursary administrators

Fees and Fines is the pricing catalogue for campus charge lines: general fees, fines, graduation, registration, student card, and related amounts. Chips filter the catalogue; Configure rates changes a line amount.

Payment Plans (linked desk) define instalments when a charge is paid over time. This catalogue feeds quotes and expected amounts used elsewhere; it is not the admissions fee-proof queue.

  • Change rates carefully — they affect new quotes and expected payments.
  • Application fee verification for applicants remains on Admissions Payments.
