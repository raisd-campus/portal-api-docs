Nightly batch sequence

From cyberjayabatchnight*.sh: stop httpd, run domain SQL jobs, restart httpd, then mysqldump portal sync exports. CAP-53 must assume these jobs refresh balances, attendance, portal flags, and reports overnight.

Semester registration

ProgramsAllowedToRegister → modules → fees

Atomic with triggers; finish with bursary student refresh.

flowchart TD
  Gate[ProgramsAllowedToRegister] --> Sem[Insert/update r_stdsemester]
  Sem --> Mod[Insert/update r_stdmodule]
  Mod --> Trig[Fees / registration triggers]
  Trig --> Upd[b_Update_Student]
  Upd --> Out[AccOutstanding / CGPA consistency]

Do not bypass b_Update_Student (and related mark/billing variants) when mutating registration or balances — overnight batch and desk UIs assume these procedures keep outstanding and academic aggregates consistent.

Portal login gating

Batch portal.sql enables/disables student portal login using outstanding balance, VIP, PTPTN rules, and StdPortalActive — writing r_student.LoginActive / loginactive.

portal.sql LoginActive rules

Raisd CAP-01 must honour equivalent policy, not invent open access.

flowchart TD
  Batch[portal.sql nightly] --> Eval{Evaluate student}
  Eval -->|Outstanding / policy fail| Off[LoginActive = off]
  Eval -->|VIP / PTPTN / StdPortalActive OK| On[LoginActive = on]
  Off --> Portal[Legacy portal / sync reject]
  On --> PortalOK[Legacy portal allow]
  Sync[portal_r_student_cyberjaya dump] --> Portal
  Sync --> PortalOK

Raisd vs old write path

PHPMaker desks write MySQL directly (triggers fire in-process). Raisd portals must go Portal API → ACL → CMS, and only treat the write as success after CMS acknowledgment.
