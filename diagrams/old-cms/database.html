Implications for CAP-53

Survive triggers Inserts/updates on hot tables fire BEFORE/AFTER chains. ACL must use CMS-approved write paths.
LoginActive rules Portal session policy must honour outstanding / VIP / PTPTN / StdPortalActive gating.
b_Update_Student Do not bypass for balance/CGPA consistency after registration or finance mutations.
Idempotent writes Nightly batch may recompute flags and aggregates — API retries must reconcile.
Risk If ignored Mitigation
Raw INSERT into r_student Missing seeded related rows; orphan contacts Call CMS enrol path that expects AFTER INSERT seeding
Skip b_Update_Student Stale AccOutstanding / aggregates vs Bursary screens Invoke refresh after registration/finance writes
Ignore portal.sql Students blocked (or wrongly allowed) vs Raisd session Map LoginActive policy into CAP-01 / authz
Write during httpd-stop window Race with nightly jobs Ops runbook + retry/idempotency
Treat api_student_* as OpenAPI Leaky legacy contracts Translate via ACL; keep canonical DTOs clean

First CAP-53 slice recommendation: auth + applicant create/read + document metadata acknowledgment (using app_* and Agent* discovery), then semester registration.
