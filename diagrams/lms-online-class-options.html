Working Group verdict (research)

1 · Demo spike
Whereby Embedded or Daily Prebuilt Prove timetable-gated join, participant role, recording link, attendance webhook inside Student/Lecturer shells. Lowest ops on UltaHost k3s.
2 · Education pack
Managed BigBlueButton + Portal API Best OSS classroom depth: excellent teaching UX, native Moodle, built-in attendance analytics. Prefer managed host — do not self-host media on the Demo node.
3 · OSS embed alt
OpenVidu Meet Community + Portal API Good classroom features, white-label, REST/embed. Raisd builds attendance analytics and LMS glue. Dedicated media VPS — not Demo k3s.
4 · Branded product
RealtimeKit · Chime SDK · LiveKit Best match to Faid UX pack (lobby, roster, moderated share queue). Chime strong on $/mo; RealtimeKit for breakouts later; LiveKit for self-host escape. Quizzes stay Raisd-native.

Deprioritise as primary pilot: self-hosted BBB/OpenVidu/Jitsi on current Demo VPS; Jitsi as classroom SoT (basic features); Meet/Teams-only unless a campus already standardises on them; raw Agora unless APAC scale forces it. Self-developed OSS SFU is a later path after a Cloud/SDK spike.

Raisd constraints (from standup + architecture)

  • Classroom must feel integrated — not a separate product chrome break.
  • Students join as participants; lecturers/moderators host.
  • Join access gated by class timetable.
  • Join/leave events feed attendance (late arrivals).
  • Recordings available when students miss live.
  • Quizzes attach at module / study-planner setup; self-paced unlock may differ from teaching-week release.
  • Portals talk only to Portal API (+ SSO). Meeting tokens minted server-side.
  • CMS remains SoR for enrolment; live attendance is a learning event, not a second roster SoR.

Cost calculator · unit rates

SDK / minute-priced vendors (media is per attendee-minute; recording is usually per wall-clock session-minute):

attendee_minutes / month
= concurrent_classes × (students_per_class + 1 lecturer) × hours_per_week × 60 × weeks_per_month

media_cost ≈ attendee_minutes × media_rate

recording_minutes ≈ concurrent_classes × record_fraction × hours_per_week × 60 × weeks_per_month
recording_cost ≈ recording_minutes × recording_rate
  (Chime: capture_rate + concatenation_rate; + S3 storage/transfer separate)

Seat-priced vendors (Zoom Edu / Teams):

seat_cost ≈ licensed_hosts × price_per_host_month
(+ Large Meeting / webinar / cloud-recording storage add-ons if needed)

Reading the numbers. Recording is a material share of Chime (~14% at S1, ~12% at S3) because composite capture is $0.0125/min. Self-developed platform

Build Raisd’s own virtual classroom on an open SFU (recommended starting point: LiveKit self-host; alternatives mediasoup, Janus). Raisd owns UI, roles, timetable gate, attendance, breakouts, and recording export into the campus file store.

Cost shape
CapEx / OpEx, not per-min Dedicated media nodes (~$120 → $1 200+/mo by scale), TURN, object storage for recordings, monitoring. No vendor attendee-minute bill.
Build
Highest engineering Classroom chrome, whiteboard/polls (or omit), breakout room graph, recording compose, failover. Months, not a Demo spike.
Fit
When control beats time-to-market Use after a SaaS/SDK spike proves CAP-26 flows; or if data residency forbids vendor media. Prefer LiveKit Cloud first, then self-host the same APIs.
Do not self-host media on the current shared Demo k3s node. Media SFUs need isolated CPU/RAM and separate capacity planning from Portal API / portals.

Suggested Demo spike (not Live)

  1. Portal API live_class_sessions — offering, window, provider, join mode.
  2. Raisd lobby (Week / module / Materials Download / mic-cam prep) → Lecturer Start or Student Join only inside window → host vs viewer token.
  3. Persist join/leave; show roster present/enrolled (CAP-12 Demo).
  4. On recording.ready, attach Past Class / Materials-style item (session-only Demo OK).
  5. Optional stub: screen-share request toast + host Accept/Decline queue (even if v1 host-only share on provider).
  6. Provider secrets in control-plane credentials — never in portals.
