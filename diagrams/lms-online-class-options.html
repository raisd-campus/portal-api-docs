Online-class options — full analysis

Cost models, hosting, integration shapes, breakout support, recordings, quizzes, and self-paced unlock — for Raisd portals via Portal API. Proposed Not Live Demo ≠ Live.

Indicative pricing only (public list rates, late 2025–Nov 2026 USD/EUR). Re-quote before procurement. This page does not authorise a Live CAP-26 vendor. Knowledge SoT: docs/ai/architecture/lms-online-class-options.md.

Working Group verdict (research)

1 · Demo spike
Whereby Embedded or Daily Prebuilt Prove timetable-gated join, participant role, recording link, attendance webhook inside Student/Lecturer shells. Lowest ops on UltaHost k3s.
2 · Education pack
Managed BigBlueButton + Portal API Whiteboards, polls, breakouts, recording hooks without building a classroom UI. Prefer managed host — do not self-host media on the Demo node.
3 · Branded product
Cloudflare RealtimeKit (or LiveKit) Fully Raisd chrome + programmable breakouts. Higher build cost; quizzes/self-paced stay Raisd-native.

Deprioritise as primary pilot: self-hosted BBB/Jitsi on current Demo VPS; Meet/Teams-only unless a campus already standardises on them; raw Agora unless APAC scale forces it.

Raisd constraints (from standup + architecture)

  • Classroom must feel integrated — not a separate product chrome break.
  • Students join as participants; lecturers/moderators host.
  • Join access gated by class timetable.
  • Join/leave events feed attendance (late arrivals).
  • Recordings available when students miss live.
  • Quizzes attach at module / study-planner setup; self-paced unlock may differ from teaching-week release.
  • Portals talk only to Portal API (+ SSO). Meeting tokens minted server-side.
  • CMS remains SoR for enrolment; live attendance is a learning event, not a second roster SoR.

Cost calculator

SDK / minute-priced vendors:

participant_minutes / month
= concurrent_classes × students_per_class × hours_per_week × 60 × weeks_per_month

media_cost ≈ participant_minutes × rate_per_participant_minute

recording_minutes ≈ concurrent_classes × record_fraction × hours_per_week × 60 × weeks_per_month
recording_cost ≈ recording_minutes × export_rate

Seat-priced vendors (Zoom Edu / Teams):

seat_cost ≈ licensed_hosts × price_per_host_month
(+ Large Meeting / webinar add-ons if needed)

Concurrent classes ≠ total modules. Use peak simultaneous live sessions in the timetable.

Recordings

  • Vendor captures; Portal API stores metadata (session, ready_at, duration, URL).
  • Live: prefer export into Raisd file store + enrolment authz.
  • Demo: deep-link vendor URL with expiry is acceptable if labelled Demo.
  • Phase 1 attendance = live join/leave; playback analytics later if required.

Suggested Demo spike (not Live)

  1. Portal API live_class_sessions — offering, window, provider, join mode.
  2. Lecturer Start → API creates provider room as moderator; Student Join only inside window → viewer token.
  3. Persist join/leave for attendance Demo (CAP-12).
  4. On recording.ready, attach a Materials-style learning item (session-only Demo OK).
  5. Provider secrets in control-plane credentials — never in portals.
