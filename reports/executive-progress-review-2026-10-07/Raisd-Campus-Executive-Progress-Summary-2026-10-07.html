1. Executive snapshot

Raisd is delivering four modern portals — Applicant, Student, Lecturer and Staff — on the existing campus CMS through one Portal API. The Working Group selected Lesotho as the first acceptance campus (M4) on 3 Oct 2026. Product sequence remains admissions-first: confirm rules (M1) → admissions Live (M2) → core student journeys (M3) → Lesotho acceptance (M4) → other campuses (M5).

Since the 5 Oct pack, the Demo estate has taken a material step on the admissions path: the hosted Portal API now runs Student schema v4 and exposes Applicant Demo HTTP, with the Applicant portal wired to that API in production Demo hosting. That improves platform readiness and admissions Demo depth. It does not move Live %.

3. What moved since 5 October

Hosted Portal API Student Demo schema now v4 after Neon backup and controlled reseed. Applicant Demo RPC is live (/v1/auth/applicant/login, /v1/applicant/:method).
Applicant portal Production Demo build calls the Portal API when configured. Local development can still use the in-process mock. Development Admin Actions stay mock-only.
Public documentation OpenAPI 0.4.2, PoC page, SDD increments, and AI knowledge published on GitHub Pages.

Still not Live: CMS-acknowledged writes, durable evidence bytes, production applicant identity, Registry/staff admissions desks, and Lesotho government-parity acceptance.

4.4 Definition of done (any capability)

  1. Real data from the system of record (not a mock session).
  2. Durable save where the user can mutate data.
  3. Server-enforced permission for that role and campus.
  4. Paired staff/lecturer action exists in new UI or is verified in the old CMS.
  5. Accountable owner named.
  6. Core mobile accepted if the capability is in the mobile product set.
  7. Country/campus operating checks closed or explicitly waived.
