3. Key technical results

CAP-53 (CMS ↔ Portal API)

  • Hooks exist (Botswana-class, not Sierra Leone greenfield): 5 × portal_student_*_lesotho + 6 × api_student_* / api_faculty_* SPs.
  • Campus key fits LESOTHO (Campus varchar(7)).
  • Phase R1 read mapping documented → student get* methods.
  • Writes still open: WG must decide adapter-to-old-CMS vs Schema cutover.
  • Blocked for code — need private MySQL / integration replica for portal-api lesothoRead.

NMDS (government sponsorship) ≠ Botswana DTEF

  • Old CMS uses assist provider nmds / NMDS + borrower-like AssistStdAcc.
  • Term billing via b_assistbilling* (bill nos like LSO/{YYMM}/…) — internal, not a TEF.gov POST.
  • Do not reuse Botswana DTEF / tef.gov.bw client.
  • National NMDS HTTP API still unproven (may live only in newer CMS).
  • Config debt: assist BillCurrency still RM/USD — Raisd must use LSL / M.

Admissions / flows (schema × FE)

  • 3-step review has physical columns: Faculty* → AQA* → Registry* on app_applicationform.
  • Rank / overall score seen in newer UI — not in old application table columns (confirm with campus).
  • LGCSE: flat education subjects + document tables; need campus extract model (Sesotho).
  • Online enrolment path: online_enrollment + payment verification SPs.
