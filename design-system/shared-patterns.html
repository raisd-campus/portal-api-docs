Applicant portal

Applicant enrolment confirmation

#

Historical 0.6.1 captures retain the earlier single-confirmation flow. New 0.6.2 v2 captures show QA Eligibility confirmation followed by Registry Offer acceptance, with spaced equal-width icon actions, native PDF preview in a new tab and filename-preserving download. Overall review remains orange until final acceptance; four checks separately track payment, documents, applicant confirmation and Registry Offer release. Applicant owns approved-enrolment acceptance and the development next-login workflow. This composition uses the released 0.6.1 Popup, DetailField and buttons unchanged; confirmation displays intake, faculty and programme and explains automatic logout followed by an explicit Sign in click. Failed logout keeps accepted status and retries only logout. Captures are from an uncommitted Applicant working tree, not a new package release or live authentication.

Applicant portal

Applicant save before leaving

#

Released 0.6.2 Popup adds footerAfterDismiss for a consumer-owned primary action after standard dismissal. Applicant saves incomplete drafts before the originally blocked navigation, locks pending dismissal and keeps fields/files on failed save. Visual and keyboard order is Discard Changes, Keep Editing, Save & Close; the last action wraps on phone. Workflow belongs to Applicant and introduces no HTTP persistence.

Applicant guidance · @raisd-campus/design-system/system/popup

Applicant portal

Applicant review progress

#

Application Progress uses Step as its first column. The orange Under review summary remains open through Eligibility confirmation and Registry Offer release. Four ordered rows independently report Bursary payment, Quality Assurance documents, applicant confirmation and Registry preparation/release. Only final Enrolment Accepted completes the overall review. These are uncommitted Applicant composition captures using shared 0.6.2, not new hosted operations.
